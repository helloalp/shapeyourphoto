# 用户可见语言规范

- 设置中的 `language` 是当前唯一语言偏好入口，默认 `zh_CN`，支持 `zh_CN`、`en_US`、`ja_JP`，旧设置文件缺失该字段时自动补默认值。
- `src/ui/language.py` 负责语言选项、规范化和当前语言状态；不得另起第二套 i18n 框架。
- `src/ui/display_names.py` 负责把内部 code/enum 转成用户可读显示名；业务存储、判断和日志结构继续保留英文内部值。
- 1.2.6 起新增或重构的菜单、顶栏按钮、筛选下拉、列表/清理表头、右侧标签、帮助入口、扫描规则 UI、更新历史 v1.2.6 条目必须进入语言层或多语言结构；历史硬编码中文可继续分批收敛。
- 语言偏好保存后，已创建主窗口的主要导航和操作文案必须实时刷新；筛选下拉可显示当前语言，但内部筛选语义必须继续使用稳定 code，避免切换语言后筛选失效。
- 普通用户界面避免直接展示 `cleanup candidate`、`no-op`、`critical`、`version_id=`、`build_id=`、颜色 token、更新 URL、公告 URL 和实现解释。
- 更新页可展示 `Shape Your Photo vX.Y.Z` 和“版本 ID N”；构建 ID 只留在内部元数据和协议比较里。
- 删除、清理、更新和公告错误弹窗使用简短中文说明；详细异常写入 Console。
- 普通 UI 优先使用“文件夹”，只有技术文档或代码注释需要精确术语时才使用“目录”。
- “候选”不作为普通 UI 的主要称呼；删除/保留复核语境使用“不适合保留的图片”“待清理”，修复语境使用“待修复”。
- 用户可见列表中的严重程度、原因、状态必须经过显示名映射，不直接展示内部 enum。
- 更新历史面向普通用户展示时使用版本分组和编号列表；v1.2.6 起优先使用当前语言条目，旧版本没有翻译时回落到中文事实记录。Markdown 符号、反引号和内部 debug 词应在 UI 层转成自然中文。
- 版本记录写“发生了什么”和“用户/功能层面的结果”，不写开发过程闲话、AI 协作过程或“按用户要求”等交代式措辞。

## 1.2.6 继续升级后的维护要求

- 维护任何 UI 文案前必须先读本文件；新增窗口、按钮、状态反馈、设置项和选项值必须同步 `zh_CN`、`en_US`、`ja_JP`。
- 非英语界面下的顶部 `Language` 是固定英文快捷入口，用于帮助用户快速找回语言设置；它不是翻译遗漏。
- 设置页不得只翻译页签标题。每个页签内的标题、说明、下拉选项、按钮、状态和错误提示都必须随语言即时刷新。
- GPU、性能、EXIF、统计、帮助、扫描和修复取消相关页面面向普通用户，不得把 requirements、后端清单、内部模块名或维护说明作为主要操作提示。需要排查时提供复制诊断、帮助链接或明确下一步。
- ShapeYourPhoto 是软件名，不翻译；含 ShapeYourPhoto 的元数据保护提示使用“此项由软件保留”等自然表达，不解释保护算法。
