# 用户可见语言规范

- 设置中的 `language` 是当前唯一语言偏好入口，默认 `zh_CN`，旧设置文件缺失该字段时自动补默认值。
- `src/ui/language.py` 负责语言选项、规范化和当前语言状态；不得另起第二套 i18n 框架。
- `src/ui/display_names.py` 负责把内部 code/enum 转成用户可读显示名；业务存储、判断和日志结构继续保留英文内部值。
- 当前收口只完成基础设施、显示名映射和已触碰窗口的文案清理；主界面核心面板的大规模硬编码文案替换应作为单独任务处理。
- 普通用户界面避免直接展示 `cleanup candidate`、`no-op`、`critical`、`version_id=`、`build_id=`、颜色 token、更新 URL、公告 URL 和实现解释。
- 更新页可展示 `Shape Your Photo vX.Y.Z` 和“版本 ID N”；构建 ID 只留在内部元数据和协议比较里。
- 删除、清理、更新和公告错误弹窗使用简短中文说明；详细异常写入 Console。
- 普通 UI 优先使用“文件夹”，只有技术文档或代码注释需要精确术语时才使用“目录”。
- “候选”不作为普通 UI 的主要称呼；删除/保留复核语境使用“不适合保留的图片”“待清理”，修复语境使用“待修复”。
- 用户可见列表中的严重程度、原因、状态必须经过显示名映射，不直接展示内部 enum。
- 更新历史面向普通用户展示时使用版本分组和编号列表；Markdown 符号、反引号和内部 debug 词应在 UI 层转成自然中文。
- 版本记录写“发生了什么”和“用户/功能层面的结果”，不写开发过程闲话、AI 协作过程或“按用户要求”等交代式措辞。
